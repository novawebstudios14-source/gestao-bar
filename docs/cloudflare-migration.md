# Migração para a conta Cloudflare do cliente

1. Exporte o D1 da origem com acesso autorizado (`wrangler d1 export <banco-origem> --remote --output /caminho/privado/backup.sql`) ou faça uma cópia consistente de seu SQLite pelo mecanismo de backup da origem; não copie um arquivo aberto durante vendas. Guarde o backup em local privado. Registre `SELECT COUNT(*)` de `products`, `bar_tables`, `table_sessions`, `recipes` e `movements`, além de `PRAGMA foreign_key_check`.
2. Na conta Cloudflare do cliente, crie um D1 no plano gratuito e um Worker `workers.dev`. Configure o binding `DB` para esse D1 e as variáveis secretas `BAR_USER` e `BAR_PASSWORD` no Worker. Não inclua valores no GitHub. Rode `pnpm build`, depois `node scripts/prepare-cloudflare-deploy.mjs <ID-REAL-DO-D1> <NOME-DO-D1> <NOME-DO-WORKER>`; o comando altera só o arquivo ignorado `dist/server/wrangler.json`. Faça a publicação com `wrangler deploy --config dist/server/wrangler.json` na conta do cliente, após configurar os segredos com `wrangler secret put BAR_USER --config dist/server/wrangler.json` e `wrangler secret put BAR_PASSWORD --config dist/server/wrangler.json`.
3. Execute as migrações `drizzle/0000_*.sql` a `0005_*.sql` na ordem numérica em um D1 **vazio**. Elas criam a estrutura final atual. Confirme a estrutura antes de importar.
4. Execute `node scripts/export-to-d1.mjs /caminho/backup.sql /caminho/privado/import.sql` (ou use `backup.sqlite`) fora do repositório. Confirme que `foreignKeyErrors` é zero. Execute o SQL no novo D1 com `wrangler d1 execute <nome-do-D1> --remote --file=/caminho/privado/import.sql` usando a sessão autenticada do cliente. Se a importação falhar parcialmente, descarte somente o D1 novo ainda não usado e recomece em um D1 vazio; não acrescente dados sobre importação incompleta.
5. Confira novamente as cinco contagens, `PRAGMA foreign_key_check`, IDs máximos, somas de `price_cents`, `stock`, `quantity`, `unit_price_cents` e `unit_cost_cents`, datas mínimas e máximas e sessões abertas/pagas. O export preserva colunas e IDs originais. Não publique o arquivo SQL nem o SQLite.
6. Teste cada fluxo em um D1 separado para testes e confirme que uma nova implantação preserva os dados. Registre CPU por requisição, contadores diários de Worker e leituras/escritas D1 no painel Cloudflare. Compare com os limites atuais da conta antes de prometer custo zero.
7. Na troca final, interrompa temporariamente novos lançamentos na origem, obtenha um **novo** backup consistente, repita a exportação e a importação em D1 de produção limpo e confira as contagens. Só após os testes atualize `index.html` e `docs/index.html` para o Worker. Se houver divergência, mantenha o link antigo e permita vendas apenas na origem. Preserve origem e backup para reversão; vendas efetuadas no novo endereço exigem reconciliação antes de retornar ao antigo.
